# oddity

奇数項なら式、偶数項なら宣言。**項数の奇偶が意味を決める**ジョーク言語の Rust 実装。

仕様は [docs/spec.md](docs/spec.md)。

```sh
cargo build --release
cargo run -- examples/fizzbuzz.odd
cargo run -- -e '1 <<< "Hello, world!\n"'
cargo run -- --ast examples/fact.odd    # 項の入れ子だけ表示（結合は実行時に決まるので出せない）
cargo test
```

```
(n fact d
    (n <= 1) ? 1 : {n * ((n - 1) fact d)}
) ;
1 <<< "10! = " <<< (10 fact ()) <<< "\n"
```

## サイト

`docs/` が GitHub Pages 用の公式サイト。**インタプリタ本体をそのまま WebAssembly にして**プレイグラウンドで動かしている。

```sh
./tools/build-wasm.sh                    # docs/oddity.wasm を作り直す
cd docs && python3 -m http.server 8000   # http://localhost:8000
node tools/check-site.mjs                # 載せた出力が本当にその出力か照合する（速い）
./tools/check-browser.sh                 # 本物の Chrome で描画して検査する（5秒）
```

検査が2段あるのは、**片方では捕まらない不具合があるため**。`check-site.mjs` は DOM を偽装して `app.js` を読み込むので、実行とハイライトは本番と同じ経路を通るが、`getElementById` が返す要素までは再現しない。実際に `<section id="hl">` とプレイグラウンドの `<code id="hl">` が衝突して、ハイライトの節がプレイグラウンドのコードで丸ごと上書きされる不具合を出したことがある。いまは前者が id の重複を静的に、後者が描画後の DOM を見て、どちらでも捕まる。

公開するには GitHub の Settings → Pages で **Source を「Deploy from a branch」、branch を `main`、folder を `/docs`** にする。ビルドは要らない（`docs/oddity.wasm` はコミットされている）。`docs/app.js` の先頭の `REPO` だけ公開先に合わせて直すこと。

| ファイル | 中身 |
|---|---|
| `docs/index.html` | ランディング。概念・プレイグラウンド・ツアー・地雷・ギャラリー |
| `docs/spec.html` | `docs/spec.md` をブラウザで描画する。サイトが仕様から遅れない |
| `docs/app.js` | wasm の口、位置ハイライト、プレイグラウンド |
| `docs/oddity.wasm` | `src/wasm.rs` のビルド成果物。import ゼロ・127KB |
| `tools/check-site.mjs` | サイトの主張を機械で検算する。`app.js` を実物ごと読み込んで走らせる |
| `tools/check-browser.sh` | Chrome を headless で走らせ、JS が動いたあとの DOM を検査する |

**ハイライトは処理系本体がやっている。** 順位が実行時の値なので構文ハイライトは原理的に不可能（§4.3）だが、**役割**は括弧の対応が取れた時点で確定する（§0）。`src/roles.rs` がその役割を返し、サイトはそれを塗るだけ。だから `a = = b` の2番目の `=` が「関数名」の色で出る。

## 構成

| ファイル | 担当 |
|---|---|
| `src/lexer.rs` | §1 字句。空白が唯一の区切り。`"` と `//` はトークン先頭のときだけ特別 |
| `src/parser.rs` | §2 括弧。**木にせず平坦な項の列**として保持する。ここでの検査は「2項＝構文エラー」だけ |
| `src/eval.rs` | §4 グルーピング（評価直前に順位を環境から引く）と §2/§3 の評価 |
| `src/env.rs` | §6 フレーム連鎖とプレリュード（順位表はここ） |
| `src/builtins.rs` | §8 プレリュード演算子の中身 |
| `src/value.rs` | §7 値。数・文字列・関数・cons・ユニット、および記号項 |
| `src/io.rs` | §8.4 fd テーブル |
| `src/roles.rs` | §0 位置から決まる役割。サイトのハイライトはこれ |
| `src/wasm.rs` | ブラウザ向けの C ABI。素の wasm で wasm-bindgen は使わない |

パイプラインは
**字句 → 項の入れ子（平坦なまま） → 〔評価直前〕グルーピング → 評価**
で、3段目が実行時に何度でも走るのがこの言語の肝である。関数本体は呼び出しのたびにグルーピングし直される（§4.5）。

レキサとパーサは `;` と `+` の区別を一切持たない。字種の知識は
**数値フレーム（`src/env.rs` の `numeric_frame`）1箇所** だけにある（§0, §6.1）。

## 仕様が黙っていたところ

実装にあたって決めた点。いずれも仕様本文とは矛盾しないはずだが、明文化はされていない。

- **シグネチャの項がトークンでないとき**（`(A) ; (B) (C)` のように `;` を書き忘れた形）
  は **エラーにしない**。§2.4 が「静かに関数宣言に化ける（エラーは出ない）」と要求するため。
  引数名でない位置に来た引数は評価だけされて捨てられ、名前を持たない宣言は束縛されずに関数値だけを返す。
- **記号項の印字**は `(x + y)` のようにソースの見た目に戻す。組み込み関数は綴りで、
  ユーザー定義関数は `<fn 名前>` で出る（§10 の「関数を印字する」が観測できるように）。
- **cons の印字**は左スパインを平坦に並べる。`((1 , 2) , 3)` は `(1 , 2 , 3)`、
  `(1 , (2 , 3))` はそのまま（§8.2 の「左ネストは見えない」がそのまま印字に出る）。
- **算術のオーバーフローと 0 除算**は記号項を返す。例外が無い言語なので、
  「計算できないものは記号のまま残る」（付録）に寄せた。数は i64。
- `~` は左が文字列でないとき、基数が 2..=36 でないときも `()` を返す。
- **stdout は行バッファ、stderr は無バッファ。** §10 最後の地雷（`!!` で progress が消える）を
  実装で再現している。掃き出す契機は「正常終了」と「`>>>` がブロックする直前」の2つだけで、
  後者は §8.4 の「読み取りは書き込みを追い越さない」を担保するもの
  （`IoTable::flush_all`）。`!!` はどちらの契機も持たないので地雷は残る。
- `<<<` の書き込み先が存在しない fd なら黙って捨てる（`2 = 5` で標準エラーが消える経路）。
- プログラムの評価値は捨てて既定で 0 終了。終了コードを設定するのは `!!` だけ（§9）。
  構文エラーなど処理系側の失敗だけは 1 で返す。
- ループは再帰だけなので、インタプリタは 256MB のスタックを持つスレッドで走る。
  それでも足りない場合に落ちるより言うほうが親切なので、深さ 50,000 段で打ち切る
  （ブラウザは 500 段。V8 の wasm フレームはネイティブスタックを使うため）。
