# oddity

oddity は、二項演算子を定義して、適用するプログラミング言語です。このリポジトリには、Rust 製の処理系、実行例、ブラウザで試せるプレイグラウンドを収録しています。

- [紹介サイト・プレイグラウンド](https://todays-mitsui.github.io/oddity/)
- [言語仕様](docs/spec.md)（[ブラウザで読む](https://todays-mitsui.github.io/oddity/spec.html)）

## 定義して使う

```text
(a plus b a + b) ;
1 <<< (2 plus 3)
```

標準出力に `5` を表示します。

先頭の括弧内では、`a plus b` が「左仮引数・演算子名・右仮引数」、残りの `a + b` が本体です。定義した `plus` は、`+` と同じ中置の形で使えます。すべての関数は2引数で、関数呼び出しと二項演算子の適用は同じ書き方です。

`;` は左右を順に評価して右の値を返す演算子、`1 <<< 値` は標準出力へ書き込む式です。裸の式の評価値は、自動では表示されません。

## 基本の仕組み

名前は字種によって演算子と変数に分かれません。式では奇数番目がオペランド、偶数番目がオペレータです。`x + y` と `x plus y` は同じ構造を持ち、`x+y` は全体で一つの名前になります。

式は「オペランド・演算子・オペランド……」と並ぶため、奇数項になります。oddity は4以上の偶数項を関数定義として扱います。最初の例の定義は、シグネチャ3項と本体3項の計6項です。括弧でまとめた部分は外側から1項と数えます。0項はユニット値、2項は構文エラーです。

代入や条件分岐も演算子で表します。ただし評価方法は演算子によって異なり、`?` や `:` は右辺を必要な場合だけ評価します。優先順位は実行時の束縛から取得します。例えば初期環境では `+` と `*` が同順位・左結合なので、`1 + 2 * 3` の評価値は `9` です。

詳しい規則と注意点は[言語仕様](docs/spec.md)を参照してください。

## ローカルで実行する

Rust と Cargo が必要です。処理系は外部クレートに依存していません。以下のコマンドはリポジトリのルートで実行します。

```sh
git clone https://github.com/todays-mitsui/oddity.git
cd oddity
cargo build --release
```

ファイルを指定するか、`-e` でソースを直接渡します。

```sh
./target/release/oddity examples/fizzbuzz.odd
./target/release/oddity -e '1 <<< "Hello, world!\n"'
```

`--ast` は、評価前の項数と項の入れ子を表示します。演算子の結合は評価時に決まるため、この表示には含まれません。

```sh
./target/release/oddity --ast examples/fact.odd
```

`examples/` には階乗、FizzBuzz、リストの畳み込み、標準入力の読み取りなどの例があります。名前の末尾が `_` のファイルは、名前を置き換えた難読化版です。

## サイトをローカルで確認する

`docs/` は GitHub Pages 用の静的サイトです。プレイグラウンドは、同じ Rust 処理系を WebAssembly にビルドした `docs/oddity.wasm` を使用します。

コミット済みの Wasm を使う場合は、Python 3 で HTTP サーバーを起動できます。リポジトリのルートで実行し、[http://localhost:8000](http://localhost:8000) を開いてください。

```sh
python3 -m http.server 8000 --directory docs
```

Rust の実装を変更した場合は、サイトの検証前に Wasm を再ビルドします。スクリプトは rustup で `wasm32-unknown-unknown` ターゲットを追加し、生成物を `docs/oddity.wasm` へコピーします。

```sh
./tools/build-wasm.sh
```

コードの色分けには、処理系のレキサとパーサが判別した役割を使います。項の位置から分かるオペランド・オペレータ・定義の名前を表示し、実行時の環境に依存する演算子の結合とは区別しています。

## 検証する

リポジトリのルートで実行します。

```sh
cargo test
node tools/check-site.mjs
./tools/check-browser.sh
```

- `cargo test`：処理系の規則と実行例を検証します。
- `check-site.mjs`：Node.js 上でサイトの Wasm と JavaScript を使い、掲載例の出力、例題の実行、ハイライト、DOM ID の重複、仕様 Markdown の変換を確認します。
- `check-browser.sh`：Chrome または Chromium と Python 3 を使い、描画後の DOM、プレイグラウンドの初期実行、ハイライト、仕様ページの目次を確認します。ブラウザが見つからない場合はスキップします。

サイトの検証には Node.js が必要です。Wasm を読み込む検証と、実際のブラウザで描画する検証を分けることで、出力の不一致と DOM・表示上の不具合をそれぞれ確認します。

## 実装の構成

処理は「字句解析 → 項の入れ子の解析 → グルーピング → 評価」の順に進みます。括弧内の項列は平坦に保持し、その括弧を評価する直前に優先順位を取得してグルーピングします。関数本体も呼び出しのたびにグルーピングします。

- `src/lexer.rs`：名前、引用文字列、括弧、コメントの字句解析。
- `src/parser.rs`：項の入れ子の解析、括弧の対応と2項の検査。
- `src/eval.rs`：グルーピング、関数定義、適用、評価。
- `src/env.rs`：環境と名前の解決、プレリュードの束縛とメタデータ。
- `src/builtins.rs`：組み込み演算子、束縛パターンの検査。
- `src/value.rs`：値、比較、印字。
- `src/io.rs`：fd ごとの入出力とファイル操作。
- `src/roles.rs`：ハイライトに使う項の役割の判別。
- `src/wasm.rs`：ブラウザ向けの実行・解析 API。

言語の規則と処理系固有の動作は、[言語仕様](docs/spec.md)にまとめています。整数の範囲、算術失敗時の記号項、印字、入出力、実行の制限もそちらを参照してください。

## サイトの構成と公開

- `docs/index.html`：言語の紹介とプレイグラウンド。
- `docs/spec.md`：言語仕様の本文。
- `docs/spec.html`：`spec.md` を読み込み、HTML として表示するページ。
- `docs/app.js`：Wasm の呼び出し、ハイライト、プレイグラウンドの例題と操作。
- `docs/style.css`：サイトのスタイル。
- `docs/oddity.wasm`：ブラウザ用のビルド成果物。

GitHub Pages の公開元は、Settings → Pages で「Deploy from a branch」、ブランチ `main`、フォルダー `/docs` に設定します。Wasm はコミット済みなので、公開時に Rust をビルドする手順はありません。処理系を変更した場合は、再ビルドした Wasm もコミットします。

別のリポジトリで公開する場合は、`docs/app.js` の `REPO` と、HTML・README 内のリポジトリおよびサイトへのリンクを公開先に合わせて変更してください。
