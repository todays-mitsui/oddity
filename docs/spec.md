# oddity — 言語仕様（暫定）

奇数項なら式、偶数項なら宣言。**項数の奇偶が意味を決める**言語なので oddity。

## 0. コンセプト

規則は2つである。

1. **適用はすべて中置の二項適用である。** 関数呼び出し構文は存在せず、すべての関数は2引数を取る（§3）。
2. **トークンに字種の区別はない。** 空白だけがトークンを切り、オペレータとオペランドは綴りではなく括弧の中の位置で決まる。奇数番目がオペランド、偶数番目がオペレータである。

残りはこの2つから自然に導出される。

- 式は「オペランド（オペレータ オペランド）\*」の形しか取れないので必ず奇数項になる。偶数項が空くので、そこに関数宣言を割り当てた。項数の奇偶が式と宣言を分ける（§2.1）
- パーサはトークンが `;` か `+` かを知りようがないので、静的な優先順位表を持てない。優先順位は束縛の属性になり、実行時に環境から引かれる（§4）
- 優先順位・数体系・制御構造はすべて実行時データとしてプレリュードに置かれる
- 束縛のないトークンは自分の綴りと同じ文字列に評価されるので、未定義エラーが存在しない（§6.1）
- ユーザー定義の関数とプレリュードの演算子は同格である。任意のトークンをオペレータ位置に置けるため、`((n - 1) fact d)` `(xs , x = list)` `(b ? t : f)` はいずれも `(オペランド オペレータ オペランド)` の1形に収まり、制御構造も分割代入も専用の構文を持たない（§3, §8）

この2つが縛るのはレキサとパーサだけである。環境（プレリュード）が字種を知っていることは違反ではない。数値フレーム（§6.1）は数字列を数に解決するが、それは束縛の解決であって字句の規則ではない。

## 1. 字句

### 1.1 区切り

**空白が唯一の区切り。**

```
(x + y)    3項 → 演算
(x+y)      1項 → `x+y` という名前の変数への参照
1-1        1トークン（数ではない）
(1 - 1)    3項 → 0
```

### 1.2 予約文字

| 文字 | 予約の範囲 |
|---|---|
| `(` `)` `{` `}` | 全域予約。自己区切り（`a(b` は3トークン） |
| 空白 | 全域予約 |
| `"` | **トークン先頭のときだけ**特別 |
| `//` | **トークン先頭のときだけ**特別。行末までコメント |
| `\` | **文字列モードの中だけ**特別 |

`x"` `a\b` `<<<` `a//b` はすべて普通の識別子として合法。トークン先頭が `"` と `//` の両方に見える場合は `"` が勝つ（`"a//b"` は `//` を含む文字列）。

`//` は文字ではなく**トークンの接頭辞**を予約している。予約のカテゴリとしてはこれだけが例外。

### 1.3 引用（文字列リテラル）

`"` で挟み、`\` でエスケープする。`"abc"` は文字列 `abc` に評価され、環境を引かない。

引用は型を導入しない。束縛のないトークンも自分の綴りと同じ文字列に評価されるので（§6.1）、`"abc"` と未束縛の `abc` は同じ値である。引用が変えるのは環境を引くかどうかだけである。

- 束縛の有無に関わらず綴りが保たれるので、`1 <<< "disk full"` は必ずその文字列を印字する
- 空白や予約文字を含めてよい。`"hello world"` は空白を含む文字列
- `"1"` は文字列 `1` であって数 1 ではない。数値フレーム（§6.1）を通らないので `"1" + 1` は記号項になる
- これが §6.4 の un-shadow 手段になる。`1 = 2` の後でも `"1"` は文字列 `1` を返す

**引用文字 `"` は再束縛できない。** 理由は2つ。(a) `"` はトークン先頭で引用を開始するので、名前として綴れない（`" = '` は未終端の文字列としてレキシングされる）。(b) グルーピングは括弧の中身に対して行われるので括弧の対応が先に確定していなければならず、プログラム全体は暗黙の括弧（§2.4）であるため、**ファイル全体のトークナイズが最初に1回**走る（§4.5）。評価中の再束縛がそのファイル自身のトークナイズに影響する余地がない。

順位の変更は木の形しか変えないが、引用文字の変更は**トークン列の切れ目**を変え、括弧の対応そのものを動かす（`"("` の `(` が引用の内か外かで数が変わる）。実行時依存の度合いが1段深い。

### 1.4 名前に使える綴り

`=` の左辺（§8.1）に書けるのは**引用符なしのトークン**だけ。したがって予約文字（`(` `)` `{` `}` `"` と空白）を含む名前は定義できない。

これは意図的な放棄である。引用を常に文字列そのものに倒す以上、引用でしか綴れない名前は**定義できても参照できない**ので、最初から作れないほうがよい。

---

### 1.5 コメント

`//` から行末まで。トークンを1つも生まないので、項数には影響しない。

```
x = 1 ;        // 説明
```

**文をコメントアウトしても偶奇は保たれる。** 式は奇数項、`;` は1項なので「文＋`;`」は必ず偶数項であり、丸ごと消しても括弧の偶奇は変わらない。

ただし**ブロック最後の文は `;` を持たない**ので、そこを消すと `;` が余る：

```
a ; b ; c      5項 → 式
a ; b ;        4項 → 偶数 → 関数宣言
```

シグネチャ `a ; b`、本体 `;` の関数が宣言され、**`;` という名前の関数ができて逐次実行が壊れる**。2文のブロックなら `a ;` が2項＝構文エラーで捕まる（§2.1）が、3文以上は黙って化ける。

## 2. 括弧と偶奇

括弧の中身は木にせず、**平坦な項の列**として保持される（→ §4）。

### 2.1 偶奇規則

| 項数 | 意味 |
|---|---|
| 0 | ユニット値 `()`。`{}` も同じ（空のスコープは何も生まない） |
| 2 | **構文エラー** |
| 奇数 | **式**。奇数番目がオペランド、偶数番目がオペレータ |
| 4以上の偶数 | **関数宣言**。シグネチャ3項 + 本体（奇数項） |

0項と2項は奇偶判定の**前段**で特別扱いされる（シグネチャ3項が取れないため）。2項に意味を割り当てないのは、`=` の導入で定数宣言が不要になり、他に自然な用途がないため。**`=` の左辺形（§8.1）に続く2つ目の静的検査点**になる。

偶奇は後付けの規則ではなく**定理**である。宣言 = シグネチャ(3) + 本体(奇数) = 偶数。式が必ず奇数項であることから導出される。

### 2.2 `()` と `{}`

差は「**環境を汚すかどうか**」だけ。`{}` はフレームを1枚積む。

| | 奇数項 | 偶数項 |
|---|---|---|
| `()` | 値に評価 | 現スコープに関数を宣言し、**その関数を返す** |
| `{}` | 新スコープで評価 | **無名関数を返す**（名前は残らない） |

```
x = 1 ; {x = 2 ; (1 <<< x)} ; (1 <<< x)     → 2, 1 の順に印字
```

`{}` の偶数項が無名関数になるのは、フレームが閉じた瞬間に名前が消えるだけ、という帰結。特例ではない。

### 2.3 再帰

捨てられるフレームの中に関数自身の名前が束縛されており、クロージャがそのフレームを捕まえている。よって**`let rec` も Y コンビネータも不要**。

### 2.4 トップレベル

> **ファイル全体は暗黙のパーレンで囲まれている。**

`D ; D ; D` は5項（奇数＝式）なので走る。`;` を1つ書き忘れると偶数になり、**ブロック全体が静かに関数宣言に化ける**（エラーは出ない）。

## 3. 適用

**適用は常に中置。** 関数呼び出し構文は存在せず、演算子適用そのものが呼び出しである。

```
((n - 1) fact d)
```

**すべての関数は2引数。** 1引数が欲しければダミー引数、3引数以上が欲しければクロージャを返す。`+` も `?` も `fact` も同格。

**0引数は存在しない。** 2引数関数しか作れない世界なので、0引数の何かという値は作れない。したがって `{}` の奇数項は**新フレームで評価して値を返す**以外に解釈がなく、即時実行に確定する（§2.2 の例がそのまま成立する）。遅延は §4.4 のフラグが担うので、0引数を必要とする場面もない。

---

## 4. 優先順位

トークンが `;` か `+` かをパーサは知りようがない。したがって**静的な優先順位表は持てない**。

> **優先順位は束縛の属性であり、実行時に環境から引く。**

パーレンの中身は平坦な項列のまま保持され、評価直前に偶数番目のトークンについて順位を照会してグルーピングする（評価はしない。位置だけで演算子は判別できる）。

**グルーピング規則：最も弱い演算子のうち、いちばん右で割る**（左結合）。

### 4.1 デフォルトと初期値

未束縛トークンはデフォルト順位（**強い側**）。プレリュードの演算子はそこから下げる方向にしか動かさない。

弱い順：

```
;  <  =  <  <<< >>> !!  <  ? : ! || &&  <  == != < > <= >=  <  |> $  <  ,  <  デフォルト
```

デフォルト帯には `+ - * / % ++ <> # @ ~ <<- ->> <->` と未束縛トークンの全部が入る。同順位・左結合なので `1 + 2 * 3` は **9**、`list # n + 1` は `((list # n) + 1)`（添字が先に効く）。

`<<<` の位置は比較演算子の導入時に改訂された（当初は `,` より強い側に置いていた）。要件は2つで、`1 <<< a == b` が比較結果を印字すること、`1 <<< a , b` が対を印字すること。どちらも `<<<` が両者より弱くなければ成立しない。

### 4.2 検算

```
x = 1 ; y = x + 2 ; 1 <<< y
→ ((x = 1) ; (y = (x + 2))) ; (1 <<< y)
```

### 4.3 帰結

- `,` > `=` は**趣味ではなく必須要件**。逆だと `a , b = 1 , 2` が `(a , (b = 1) , 2)` に割れて分割代入が消える
- `=` は `? :` より弱い（確定）。`x = b ? t : f` が括弧なしで書ける代わりに、リストを畳む定型句は `(xs , x = list) : {基底}` と括弧が要る。両方を括弧から解放することはできない
- 順位は実行時の値なので**文法が実行時に書き換わる**。`, = 0` で分割代入という言語機能が消滅する。ただし効くのは以降に評価される内側の括弧から（§4.5）。構文エラーにはならない（→ §10）
- **構文ハイライトは原理的に不可能**

### 4.4 束縛のメタデータ

順位が実行時の値である以上、束縛が持つのは関数値そのものではなく**レコード**である。

| フィールド | 内容 |
|---|---|
| 関数 | 2引数関数 |
| 順位 | 数 |
| 左オペランドの評価方針 | 正格 / 遅延 |
| 右オペランドの評価方針 | 正格 / 遅延 |

未束縛トークン、およびレコード以外の値が束縛されているトークンは、**デフォルト（最強・両オペランド正格）**として扱われる。

このレコードによって §5 の「特殊形式」という概念が消える。`=` は左が遅延、`?` `:` は右が遅延、それだけの違いになる。

---

### 4.5 グルーピングのタイミング

`;` は特別な演算子ではない。文の区切りに見えるのは最弱であることの副作用にすぎず、「文ごとに割り直す」ような規則は置かない。

> 括弧の中身は、**その括弧を評価する直前に一括でグルーピングされる。**

帰結：

- **順位はグルーピング時に、関数は評価時に引かれる。** 同じ束縛の2つの側面が別のタイミングで参照される
- ブロックの途中で順位を変えても**そのブロック自身の結合は変わらない**。効くのは以降に評価される内側の括弧から
- 関数本体は呼び出しのたびにグルーピングされるので、順位変更は**その後に呼ばれた関数**には効く
- 逆に演算子の中身（関数）の差し替えは評価時に引かれるので、同じブロック内でも即座に効く（§10 の `!! = <<<`）

**演算子が何をするかは途中で変えられるが、どう結合するかは変えられない。**

## 5. 評価戦略

**正格評価がデフォルト。** オペランドは左→右の順に評価（`;` に必要なので仕様に明記）。

ただし正格性は言語の性質ではなく**束縛の属性**である（§4.4）。したがって：

> **特殊形式は存在しない。**

`=` も `?` も `:` も、遅延フラグが立っているだけの普通の2引数関数。遅延オペランドは評価されず、**構文木と呼び出し側環境の対**として渡される。`?` はそれを真のときに評価し、`=` は評価せず木として検査する。同じ機構の使い分けに過ぎない。

フラグが束縛の属性である以上、原理的には**ユーザーが自分の制御構造を定義できる**（`(cond while body)`）。ただしフラグを構成する手段＝環境を値にすることは **v1 以降に先送り**（§12）。v0 ではフラグ付き束縛はプレリュードの5つ（`=` `?` `:` `!` とそのエイリアス）に限られる。

穴が1つある。フラグは**オペレータ位置のトークンの束縛**に付いているので、`f = ?` のように関数値を取り出して渡すと遅延が失われる。`=` も同じ穴を持つ。

## 6. 環境

### 6.1 フレーム連鎖

```
最内 → ... → トップレベル → 数値フレーム → 自己評価フレーム
```

末尾2枚は表ではなく**関数で解決するフレーム**。自己評価フレームは全トークンを引き受けて絶対に失敗しないので必ず最後。

- **自己評価フレーム**：束縛のないトークンは自分の綴りと同じ文字列に評価される。未定義エラーが存在しない
- **数値フレーム**：数字列を数に解決する。数値トークンは無限個あるので表には置けない。**字種の知識はここ1箇所に集まり、`+` は数を受け取るだけの普通の関数になる**。解決器は**差し替え不可**（固定）

### 6.2 束縛規則

> **`=` は常に最内フレームに対して束縛する。そのフレームに束縛が無ければ、そこに作る。**

- `{x = 2}` … 新フレームに無い → 新規作成 → 外を隠す（関数型の束縛）
- `(a = 1 ; a = 2)` … 同一フレーム → 既存に当たる → **後勝ち**（命令型の代入）

同じ演算子が、囲む括弧の字種だけで意味を変える。

### 6.3 内側から外側は書けない

`=` が最内フレームしか触らない以上、**親フレームへの書き込み手段が存在しない**。関数本体にも同じことが効く。

- 書き換え可能なグローバル状態はトップレベルだけ、しかもトップレベルからしか触れない
- 副作用がレキシカルに封じ込められている

### 6.4 数は唯一の不変層

数値フレームは無限なので `=` がそこで既存の束縛に当たることは**原理的にない**。かつトップレベルより外側なので誰も書き込めない。

- 数の遮蔽は常に「新規作成」＝積み増し。プレリュードは壊れない
- `1 = 1 + 1` は右辺でプレリュードの 1 を読み、トップレベルに新しい束縛を作る
- **un-shadow は部分的にしかできない。** 一度潰した数字は綴りとしては戻らないが、`"1"` で文字列 `1` は取り出せる（§1.3）。ただし取り出せるのは文字列であって数ではない。数そのものが必要なら `{}` の中で生き返らせる

## 7. リテラル

リテラルは文字列リテラルだけである。整数はリテラルではなく、数値フレームが解決するトークンである（§6.1）。負数も解決器が引き受けるので単項演算子は不要。

**値の種類は 数・文字列・関数・cons・ユニット `()` の5つである。** 加えて、適用に失敗した式が記号項として残る（付録）。文字列リテラルは既存の文字列を作る構文であり、新しい型を導入しない（§1.3）。

`1` と `"1"` の間には非対称が残る。

| | 正体 | 遮蔽 |
|---|---|---|
| `1` | 名前。環境を引く | できる（`2 = 5` で標準エラーが死ぬ） |
| `"1"` | 引用された文字列。環境を引かない | できない |

`"..."` はオペレータ位置にも書ける（`(a "foo" b)`）。文字列を2引数に適用しようとして失敗し、記号項になる。レキサが判別するのは引用されているかどうかだけであり、それは型の区別ではなく環境を引くかどうかの区別なので、役割を位置だけで決める §0 の規則は文字列リテラルを入れても保たれる。

### 7.1 偽

**偽は `()` のみである。** 数の 0 も、空文字列 `""` も真である。

真理値型が存在しないため、述語として使えるのは値があるか無いかだけである。0 を偽に含めると `?` と `:` が別々の述語を使うことになり、両者の対称性が崩れる（§8.3）。

- 真理値リテラルは不要である（`()` か、そうでないか）
- `()` は `=` の手が届かない唯一の値である。空パーレンは構文であってトークンではないため、遮蔽できない。演算子・数値・リテラルがすべて再束縛可能なこの言語で、真偽の境界だけが不可侵になる
- リストに終端は無いが（§8.2）、畳み込みの停止はマッチ失敗で判定し、失敗は `()` を返す。終端判定は偽判定に一致する
- `()` はプログラム内で予期される失敗を表し、プロセスの失敗は表さない。プロセスを失敗させる手段は `!!` だけである（§8.7, §9）

## 8. プレリュード演算子

すべて普通の2引数関数。差はメタデータ（§4.4）だけ。

| | 順位 | 左 | 右 |
|---|---|---|---|
| `;` | 最弱 | 正格 | 正格 |
| `=` | ↓ | **遅延**（木として検査するだけ） | 正格 |
| `<<<` `>>>` `!!` | ↓ | 正格 | 正格 |
| `?` `:` `!` `\|\|` `&&` | ↓ | 正格 | **遅延** |
| `==` `!=` `<` `>` `<=` `>=` | ↓ | 正格 | 正格 |
| `\|>` `$` | ↓ | 正格 | 正格 |
| `,` | ↓ | 正格 | 正格 |
| `+` `-` `*` `/` `%` `++` `<>` `#` `@` `~` `<<-` `->>` `<->` | 最強（デフォルト） | 正格 | 正格 |

### 8.1 `=` — 束縛

左オペランドが遅延なので、**評価せず構文木として検査する**。

許される左辺：

- **引用符なしの**単一トークン（`1` `2` を含む）
- `,` だけで繋がれたトークンの連鎖（`()` によるグルーピングは透過）

それ以外は**構文エラー**。この言語で唯一の静的検査点。`"hello" = 5` は引用トークンなので違法（§1.4）。

```
a , b = 1 , 2        → a = 1, b = 2
x = a , b            → x = Cons a b
x = y = 1            → 構文エラー（左結合で ((x = y) = 1)）
```

**パターンは第一級ではない。** `x` の中身が cons でも、参照した瞬間ただの値。逆にすると `y = x` の意味がソースから決まらなくなる。

`=` は右辺の値を返す。

**マッチ失敗は `()` を返す。** エラーにはしない。リストに終端が無く、畳み込みの停止条件が「cons でなくなること」＝マッチ失敗である以上（§8.2）、これをエラーにすると catch の無い言語（§8.6）でリストを畳めなくなる。リストの終端は**予期される失敗**であり、§8.7 の `()` 側の住人である。

**`=` は原子的。** 形を検査してから束縛する。でないと `(xs , x = 1)` が失敗する前に部分的な束縛が残る。

**パターンの葉に `()` は許さない。** 葉は必ず束縛先であり、`=` は純粋な束縛構文である。したがって「要素数の完全一致」は表現できず、パターンは常に末尾寄せの部分マッチになる。マッチが失敗するのは**右辺の深さが足りないとき**だけ。

リストに終端が無くなった（§8.2）ことで完全一致の需要が下がったのが理由。許すと `=` が「全部束縛する構文」から「検査を含む構文」に変わり、静的検査点としての単純さが失われる。

### 8.2 `,` — Cons

左結合・左ネスト。`(a , b , c , d)` は `Cons (Cons (Cons a b) c) d`。

**終端は存在しない。** `,` は二分木を作るだけで、「リスト」とはその**左スパイン**のことでしかない。したがって：

- **空リストは存在しない。** 最短のリストは1要素であり、1要素のリストは値そのもの（`(1)` ≡ `1`）
- **左ネストは見えない。** `((1 , 2) , 3)` ≡ `(1 , 2 , 3)`。リストを要素として左側に置くと平坦なリストに吸収される。右ネスト `(1 , (2 , 3))` だけが構造として残る
- 空や入れ子を表現する必要がある場面では、`()` を終端として**明示的に使う**。言語規則ではなく慣習

**`isEmpty` は不要。** 空リストを受け取る関数が原理的に書けないため。必要なのは `isPair` であり、それは分割代入そのものである（§8.1）：

```
(xs , x = list) : {基底}
```

`list` が cons なら `=` は右辺の値を返して真、cons でなければ失敗して `()` を返して偽。**マッチが判定を兼ねる。**

パターンは**末尾寄せ**になる：

```
(rest , y , z = list)   → y, z に末尾2要素、rest に残り
```

### 8.3 `?` `:` — 分岐

`?` と `:` は独立した二項演算子である。三項演算子は存在せず、`(b ? t : f)` が三項演算子のように見えるのは、5項の式が左結合で `((b ? t) : f)` と読まれるからである。二項演算子は項を2つ足すので式は奇数項のまま保たれ（§2.1）、arity も2に閉じたままである（§3）。

両者とも左は正格、右は遅延である。偽が `()` のみなので（§7.1）、述語は「左が `()` か」の一つで足りる。

- `(b ? t)` … `b` が `()` でなければ `t` を評価して返す。`()` なら `t` を評価せず `()` を返す。ガード
- `(x : y)` … `x` が `()` なら `y` を評価して返す。`()` でなければ `y` を評価せず `x` を返す。Elvis

`?` 単体は早期リターン、`:` 単体はデフォルト値（§8.7）として使える。`(b ? 1 : 2)` は `{}` もダミー引数も要らずに書け、選ばれなかった枝は評価されない。

左を検査して片方の場合だけ右を評価する二項演算子は3種類ある。

| 右を評価する条件 | 他方で返すもの | 綴り |
|---|---|---|
| 左が非 `()` | `()` | `?` |
| 左が `()` | 左（＝`()`） | `:` |
| 左が `()` | `()` | `!` |

3つ目は unless である。`(x ! y)` は `x` が偽なら `y`、真なら `()` を返す。否定は `(x ! 1)` という退化した使い方にあたる。

`!` を組み込みで持つのは、`?` `:` だけでは否定が書けないためである。「真 → `()`」を作る手段は `?` の偽枝しかなく、それは偽のときにも `()` を返す。素朴に `(b ? () : 1)` と書くと真偽どちらでも 1 を返す（§10）。`==` も `(b == ())` が常に `()` を返すので使えず（§8.12）、`!=` も `(x != ())` が右オペランドを返す規約（§8.8）により `()` を返して必ず偽になる。

cons で包めば `?` `:` だけでも書ける。

```
{_ not b ((b ? (() , ())) : (() , 1)) # 1}
```

真なら `(() , ())`、偽なら `()` から `(() , 1)` に落ちる。どちらも cons なので `:` が誤発火せず、最後に中身を取り出す。中身は箱の右側なので、先頭から数える `#`（§8.11）では 1 番目になる。

`||` は `:` の、`&&` は `?` のエイリアスであり、挙動は完全に同一である。真理値型を持たない言語では、短絡論理演算子と null 合体演算子が区別されない。

### 8.4 `<<<` `>>>` `<<-` `->>` `<->` — 入出力

```
1 <<< x        標準出力へ
2 <<< x        標準エラーへ
0 >>> n        標準入力から n 文字読む
0 >>> ()       標準入力から1行読む

() <<- path    path を読み込み専用で開き、割り当てた fd を返す
3 <<- path     path を読み込み専用で fd 3 として開く
() ->> path    書き込み専用（切り詰め）
() <-> path    読み書き
```

**fopen は fd を返すだけ。** 実際の読み書きは `<<<` `>>>` で行う。左オペランドが fd という規約（`1 <<< x`）に揃えてあり、`()` は「fd はそちらで決めて」を意味する。これで両オペランドが埋まり、ダミー引数が要らない。

**開けなければ `()` を返す。** §8.7 の枠にそのまま乗る：

```
(fd = () <<- path) : {1 !! "cannot open"}
```

**close は存在しない。** 開いた fd はプロセス終了時にまとめて閉じられる。`!!` による異常終了も同じ経路（§8.6）なので例外がない。

デストラクタではない。fd は単なる数であり、所有権を持たない：

```
fd = () <<- path ;
fd = 5             // 参照は失われるが、ファイルは開いたまま
```

参照カウントもスコープ離脱も関与せず、**プロセス終了だけが閉じる契機**である。数は再束縛可能なので、`() <<- path` が返した 3 を別の場所で `3` と直書きしても同じファイルに触れる。長命なスクリプトは想定しない。

矢印の向きが方向を示す。`<<` `>>` を使わないのはシフト演算子のために空けておくため（§12）。追記モードは綴りが残っていない。

**`<<<` は左オペランド（fd）を返す。** したがって連鎖できる：

```
1 <<< "Hello, " <<< name <<< "\n"
```

`(((1 <<< "Hello, ") <<< name) <<< "\n")` と読まれ、すべて fd 1 に流れる。

**改行は付かない。** 連鎖で1行を組み立てる以上、各 `<<<` が改行を打つわけにはいかない。行末は `"\n"` を明示する。

代償として **tee ができない。** `(f (1 <<< x) d)` は `x` ではなく fd 番号を渡すので、式の途中に印字を挟み込めない。デバッグ印字には `;` と一時束縛が要る：

```
(t = 式 ; 1 <<< t ; t)
```

fd 番号も単なる変数なので `2 = 5` で標準エラーが消える。

矢印の向きが fd と値の関係を示す。**`>>>` は束縛しない。** 右オペランド遅延にして `(0 >>> x)` で `x` に束縛する案もあったが、それだと `=` 以外に2つ目の束縛構文ができ、§8.1 の「唯一の静的検査点」が崩れる。値を返すだけにして `x = (0 >>> ())` と書く。

**読み取りは、それまでに書かれたものを追い越さない。** `>>>` はブロックする前に、書き込み側の fd をすべて掃き出す。改行で終わらないプロンプトが読み取り待ちの裏に取り残されるのを防ぐためで、この言語には flush 手段が無い（close が無いのと同じ理由）以上、掃き出す契機は処理系が持つしかない。

`!!` はこの契機を持たない。§10 最後の地雷（`1 <<< progress ; 1 !! err` で progress が消える）はそのまま残る。

**EOF は `()` を返す。** 唯一の偽値なので、そのまま §8.7 の失敗の枠に乗る：

```
((0 >>> ()) : {終了})
```

0文字読み `(0 >>> 0)` は空文字列 `""` を返す。`""` は真（§7.1）なので **EOF と区別できる**。n 文字に足りずに EOF に達した場合は、読めた分を返す。

`>>>` が返すのは文字列なので、数として使うには `~` でパースする（§8.9）。

### 8.5 `;` — 逐次

最弱。**言語で唯一「値が捨てられる」箇所**。引数を評価して左を捨てるだけの、最も退屈な2引数関数。

### 8.6 `!!` — 中断（panic）

```
1 !! disk-full
```

終了コードを設定し、標準エラーにメッセージを流して強制終了。**catch は無い。**

- 特殊形式ではない。両オペランドを評価してから死ぬだけ
- 未束縛トークンが自己評価するので、引用符なしでメッセージが書ける
- 順位は `=` あたり。`;` より弱くすると `1 !! err ; cleanup` で cleanup がメッセージ構築中に走ってしまう
- 順位が「どこまでを message として飲み込むか」を決める。強すぎると `1 !! err + detail` の `+ detail` が永久に実行されない

**終了コードの経路は1本。** `!!` は「プログラム全体を今この値にして即座に返す」。この言語で唯一の非局所脱出で、catch が無いので**必ず最外まで飛ぶ**。プログラムの評価値は捨てられる（§9）ので、終了コードを設定する手段はこれしかない。

### 8.7 失敗の2階層

| | 表現 | 復帰 |
|---|---|---|
| 予期される失敗 | `()` | `?` `:` で処理 |
| プログラマの誤り | `!!` | 不可 |

昇格は1行で書ける（unwrap-or-die）：

```
(a , b = list) : {1 !! "not a pair"}
```

逆向きの経路は存在しない。**catch が無いことが、機構の欠落ではなく格の非対称として説明できる。**

### 8.8 `==` — 比較

> **真ならオペランドの一方を返し、偽なら `()` を返す。**

```
(x == y)     x と y が等しければその値、さもなくば ()
```

真理値が存在しない言語なので、真を表せる値は「`()` でない何か」しかない。手近な非 `()` 値はオペランド自身なので、これが唯一の自然な規約である。そして**0 が真になったからこそ成立する**（0 が偽なら `(x == 0)` が真なのに偽値を返してしまう）。

**返すのは右オペランド。** `==` では左右が観測上区別できないが、族全体（`<` `>` `<=` `>=`）で規約を揃えると左結合から**連鎖比較が無料**で出てくる。

```
(a < b < c)   →   ((a < b) < c)
```

`a < b` なら `b` が返り、続けて `b < c` を判定する。Python と同じ挙動。左を返す規約だと `a < c` になってしまい、連鎖にならない。

伝播規約が1つ要る：**`()` を受け取った比較は `()` を返す。** これで偽が連鎖の途中で消えずに末尾まで届く。

### 8.9 文字列演算

文字列は不変であり、内容は綴りそのものである。

- 内容比較（`==` がそのまま使える）
- 連結・部分列・長さについて閉じている。文字型は不要（1文字の文字列を返す）
- 不変なので別名参照の問題が起きない

```
("hello" ++ " " ++ "world")     → hello world
```

**文字列から数への経路は存在しない。** 数値フレーム（§6.1）は**ソースのトークン**を解決する機構であり、実行時の値は通らないため：

```
("1" ++ "2") + 1     → 記号項（13 にはならない）
```

明示的なパースが必要。数値フレームを値に適用する道（環境を値にする）は v1 以降に先送りしたため、v0 では組み込みの `~` を使う：

```
("42" ~ 10)     → 42
("2a" ~ 16)     → 42
("42" ~ ())     → ()   読めなければ ()
```

右オペランドは基数。`0 >>> ()` が文字列を返す（§8.4）ので、標準入力から数を読むには必ずこれを通る。

文字列 `1` と数 1 は等しくない。印字は同一なので、印字からは区別できない。

```
("1" == 1)      → ()
1 <<< "1"       → 1
1 <<< 1         → 1
```

なお `("" == "")` は `""` を返して真になる。次節で `()` が自分自身と等しくないのと対照的で、空文字列は偽ではない（§7.1）ぶん等値判定の内側に留まれる。

### 8.10 `|>` `$` — 適用

```
l , r |> op        →  (l op r)
f $ l , r          →  (l f r)
```

`,` のほうが強いので `((l , r) |> op)`。つまり `|>` は**左を uncons して op に渡す**（uncurry）。

糖衣ではない。`(l op r)` と直接書けば済むのは `op` がソースに書かれている場合だけで、`|>` の価値は**関数と引数組をどちらも計算結果として渡せる**ことにある。既存の `(x f y)` は名前で呼ぶ funcall であり、`|>` `$` が apply にあたる。

`1 , 2 , 3 |> op` は `((1 , 2) op 3)` になるので、擬似的な3引数呼び出しにも使える。§3 の「3引数以上はクロージャを返す」方式とは**互換性がない**（呼ばれる側がどちらの形式かを知っている必要がある）が、**どちらも正統としない**。プレリュードで規約を決めず、両方を残す。

代償として、**関数の引数の渡し方は契約の一部でありながら呼び出し側から見えない。** `((x f y) g z)` と `x , y , z |> f` のどちらで呼ぶべきかはソースから判別できず、間違えれば記号項が返るか分解に失敗するだけで、エラーにはならない。

**フラグ付き束縛は `|>` で正しく適用できない。** `op` はオペランド位置なので評価済みの関数値として届き、§4.4 のフラグ（オペレータ位置のトークンの束縛に付いている）が失われる。

| | `\|>` で適用すると |
|---|---|
| `=` | 左が値として届くので**束縛できない** |
| `?` `:` `!` | 短絡しない。両オペランドが評価済み |
| それ以外 | 正しく動く |

§5 で「特殊形式は存在しない」と言い切った代償がここで具体化する。**フラグ付き束縛は第一級ではない。**

### 8.11 `#` `@` `<>` — 添字と連結

```
list # n       リストの n 番目
str @ n        文字列の n 番目の文字（1文字の文字列を返す）
a <> b         リストの連結
```

添字を型で使い分けるのではなく別演算子にしてあるのは、`,` の cons と `++` の連結を別に立てたのと同じ理由。

**`#` は先頭から数える。** `list # 0` は最初の要素。`,` が左ネスト（§8.2）なので最初の要素は最深部にあり、**O(n)**（長さを測ってから降りる）。末尾から数えれば O(1) だったが、直感を優先した。`@` にはこの問題がない。

範囲外の添字は `()` を返す（§8.7 の予期される失敗）。1要素のリスト（＝値そのもの）に対する `# 0` はその値を返す。

`<>` は `b` の左スパインの要素を `a` に順に積み直すので、**コストは右辺の長さに比例する**（普通の cons リストと逆）。結合的だが**単位元は存在しない**（空リストが無いため）。モノイドではなく半群。

綴りに `<+>` や `+++` を採らないのは、前者が §10 の空白地雷を3通りに増やすため、後者が「`++` より1文字多い」＝文字数が優先順位を示すように読めるため（その案は §4 で却下済み）。

### 8.12 `()` は自分自身と等しくない

§8.8 の規約から自然に導出される。

```
(() == ())    → 両者は等しい → オペランドを返す → () → 偽
```

真を報告する手段が「非 `()` 値を返すこと」なので、`()` の等値判定は原理的に真を報告できない。実害はなく、`()` の検査は `?` `:` の仕事である（§8.3）ため `==` がそれを担う必要はない。**唯一の偽値だけが等値判定の外にいる。**

## 9. 全ては式

文という概念が存在しない。

- `=` は右辺の値を返す
- `<<<` は fd を返す（§8.4）
- 偶数パーレンは関数値を返す
- プログラム全体は暗黙のパーレンなので、**プログラムは1つの値に評価される**

> **ただしその値は捨てられる。** プログラムは既定で 0 で終了し、それ以外の終了コードを返す手段は `!!` だけである。

```
処理           // 0 で終わる
処理 ; 1 !! err  // 1 で終わる
```

値を捨てるのは「全ては式」の放棄ではない。**式の値がどこかへ行くことを、式であることは要求していない。** §8.5 の `;` は左オペランドの値を捨てるし、最外のパーレンは全部を捨てる、というだけである。

捨てないほうの設計（最後の式の値が終了コード）は、`<<<` が fd を返すこと（§8.4）と正面から衝突する。印字で終わるスクリプトは必ず 1 で終わってしまい、それを避けるには全スクリプトの末尾に `; 0` が要る。**書き忘れが即座に失敗終了に化ける定型句**を強制するのは、地雷としても質が悪い（踏んでも何も起きず、CI だけが赤くなる）。

代わりに **§8.6 の「終了コードの経路は1本」が文字どおり真になる。** 終了コードはプログラムの評価値ではなく、`!!` が明示的に表明したものだけになる。

POSIX の下位8bit により `256 !! err` は**エラーを印字して成功終了**する。`!!` の左オペランドも再束縛可能なので、成功と失敗の境界は依然としてソースの字面からは分からない（§10）。

## 10. 地雷一覧（仕様）

非自明な規則ごとにまとめる。機構は各節を参照。

空白がトークンを切る。C 系の「空白は省略できる」という直感が通用しない（§1.1）。

- `(x+y)` は `x+y` という名前への参照、`1-1` は1トークン。どちらも既存言語そっくりの見た目で別の意味
- 2文字以上の演算子に空白が1つ入ると4項＝偶数＝宣言に化け、シグネチャ2番目が関数名として潰される。`a = = b` `a ! = b` `a - >> b` すべて同じ形で、構文エラーは出ない

`//` はトークン先頭でだけコメントになる（§1.5）。

- `a // b` は整数除算に見えてコメント。行末の `)` まで食うので、括弧が崩れて遠くでエラーになる
- `x//y` は名前、`x //y` は行の残りが消える

項数の偶奇が式と宣言を分ける（§2.1, §1.5）。

- `;` の書き忘れ、またはブロック最後の文のコメントアウトで偶奇が反転し、ブロックが静かに関数宣言に化ける。2文のブロックだけは2項＝構文エラーで守られる

数リテラルは再束縛できる（§6.4）。数に意味を持たせている箇所はすべて影響を受ける。

- `1 = 1 + 1` は恒等式の顔をしたアキュムレータ
- `1 , 2 = 3 , 4` で以降のソースの算術が死ぬ。インタプリタ内部は無傷なので、純粋に字面レベルの時限爆弾
- fd が数なので `2 = 5` で標準エラーが消え、`(1 <<- path)` で標準出力が読み込み口になる（§8.4）
- 終了コードも数なので `1 = 0` で全 panic が成功終了に化ける（§9）

演算子も再束縛できる。

- `, = 0` で分割代入が言語から消える。順位が 0 になるのではなく、束縛がレコードでなくなってデフォルトに落ち、数 0 の適用が失敗して記号項になる（§4.4）。効くのは以降に評価される内側の括弧から（§4.5）
- `!! = <<<` で全 panic が警告に化ける。クロージャがフレームを捕まえているので、末尾の1行が既存の全 panic を遡って無効化する

束縛のないトークンは綴りどおりの文字列に評価される（§1.3）。

- `1 <<< hello` は `hello` を束縛した後は関数を印字する。引用符1つの有無で、意図した文字列が出るかどうかが変わる

`()` が唯一の偽値である（§7.1）。

- `(b ? () : f)` は真でも `f` を返す。否定を素朴に `(b ? () : 1)` と書くと常に 1 になる（§8.3）

以下の2つは上の規則から導出されない。

- `->>` は Perl の `>>`（追記）に見えるが切り詰め書き込み（§8.4）。追記のつもりでファイルを消す
- stdout がバッファリングされ `!!` の stderr が即時なので、`1 <<< progress ; 1 !! err` で progress が消える

## 11. 未決定事項（v0）

**なし。** v0 の仕様は確定した。

最後に処理した5件：

- **`>>>` の右オペランド** → n 文字読み／`()` で1行読み（§8.4）
- **`~` による数値パース** → 採用。右オペランドは基数（§8.9）
- **引用文字の再束縛** → **却下。** 名前として綴れず、かつファイル全体のトークナイズが評価より先に1回走るため、意味を持たせる余地がない（§1.3）
- **close** → **不要。** プロセス終了時に一括で閉じる。fd は所有権を持たない単なる数（§8.4）
- **プログラムの終了コード** → **評価値は捨てる。** 既定で 0、設定する手段は `!!` だけ。`<<<` が fd を返す以上、値を終了コードにすると印字で終わるスクリプトが必ず 1 で終わってしまうため（§9）

## 付録: 事故で手に入ったもの

**数式処理系。** `(+ * /)` は3項とも束縛が無いので自分の綴りと同じ文字列に評価され、文字列を2引数に適用しようとして失敗し、記号項というデータになる。計算できないものは記号のまま残る。正格でも無傷。

**表記法のユーザー定義。** 専用機構ゼロ。

```
一 = 1 ; 二 = 2 ; (1 <<< (一 + 二))
```

**un-shadow 手段。** `"` はクォートなので、`1 = 2` で数字を潰した後でも `"1"` で文字列 `1` が取り出せる。もっとも、取り出せるのは文字列であって数ではない。

なお当初は `"` を「予約文字を含む名前を綴る手段」として使い、`"a}b"` のような名前を定義できるようにしていた。文字列リテラルの確実性と引き換えに放棄している（§1.4）。
