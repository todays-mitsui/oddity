# oddity — 言語仕様 v0

oddity は、二項演算子の定義と適用を基本構造とするプログラミング言語である。本書は v0 の規則と、現行 Rust 処理系の動作を記述する。将来の構想は §12 に分ける。

コード中の `→` 以降は説明であり、ソースには含めない。「評価値」と「標準出力」は区別する。裸の式の評価値は自動では表示されない（§9）。例は、特記しない限り初期環境でそれぞれ独立して評価する。

## 0. 基本構造と用語

基本構造は次の2点である。

1. 適用は中置の二項適用であり、すべての関数は左右の2引数を取る。
2. 引用符なしの名前を、記号・英字・数字といった字種で演算子と変数に分類しない。式における役割は項の位置で決める。

本書では、字句解析で得る単位を**トークン**、括弧内に並ぶ構文上の単位を**項**と呼ぶ。名前、引用文字列、括弧で囲まれたまとまりは、それぞれ外側から1項と数える。式では奇数番目が**オペランド**、偶数番目が**オペレータ**である。オペレータ位置にある名前から取得する関数を、左右のオペランドに適用する。

```
x + y
x plus y
```

どちらも3項の式で、中央がオペレータ位置である。定義の先頭3項は、式とは異なり「左仮引数・関数名・右仮引数」として読む（§2.1）。

式が奇数項になることは二項適用の並びから従う。oddity は、4以上の偶数項を関数定義に割り当てる設計を採る。優先順位を実行時に解決すること、未束縛の名前を文字列として評価することも、この言語が採用する規則である（§4、§6）。

## 1. 字句

### 1.1 区切り

名前同士は空白で区切る。括弧 `(` `)` `{` `}` は空白がなくても区切りになる。空白にはスペース・タブ・改行など、現行処理系の `char::is_whitespace` が認める Unicode の空白を含む。

```
(x + y)    → 中身は3項
(x+y)      → 中身は x+y という名前の1項
1-1        → 一つの名前
(1 - 1)    → 評価値 0
```

`a(b)` のトークンは `a`、`(`、`b`、`)` の4個であり、外側の項は `a` と `(b)` の2個になる。トークン数と項数は同じではない。

### 1.2 特別に扱う文字と接頭辞

| 表記 | 規則 |
|---|---|
| `(` `)` `{` `}` | 引用文字列の外では常に括弧として扱い、名前を区切る |
| 空白 | 引用文字列の外で名前を区切る |
| `"` | トークン先頭で引用文字列を開始する |
| `//` | トークン先頭で行コメントを開始する |
| `\` | 引用文字列の中でエスケープを開始する |

名前の途中の `"` や `//` は通常の文字である。`x"`、`a\b`、`a//b`、`<<<` は引用符なしの名前として使用できる。`"a//b"` は `//` を含む引用文字列であり、コメントではない。

### 1.3 引用（文字列リテラル）

引用文字列は `"` で囲む。環境を参照せず、エスケープ処理後の内容を文字列値として返す。

| エスケープ | 内容 |
|---|---|
| `\n` | 改行 |
| `\t` | タブ |
| `\r` | 復帰 |
| `\0` | NUL |
| `\e` | ESC（U+001B） |
| `\\` | バックスラッシュ |
| `\"` | 引用符 |

それ以外の `\` に続く文字は、その文字自体になる。例えば `\q` は `q` になる。引用文字列には直接の改行も含められる。閉じる引用符がない場合は字句エラーとなる。

未束縛の名前 `abc` と引用文字列 `"abc"` は同じ文字列値を返す。ただし、`abc` に束縛があれば前者はその値を参照する。`"1"` は数ではなく文字列であり、数値フレームによる解決を受けない（§6.1）。

引用を開始する `"` 自体は名前として参照・再束縛できない。字句解析は評価前にファイル全体に対して行うため、評価中の束縛変更によって引用やコメントの認識は変わらない。

### 1.4 名前に使える綴り

引用符なしの名前は、空白または括弧までの文字列である。ただし先頭が `"` または `//` の場合は、それぞれ引用・コメントとして扱う。途中にある `"` は名前に含められる（§1.2）。

束縛先や仮引数・関数名として使う場合も、引用符なしの名前を書く。引用文字列を名前の代用にはできない。したがって、空白や括弧を含む名前、`"` や `//` で始まる名前は、この方法では定義できない。

`=` の左辺には、名前だけでなく名前を組み合わせた分割代入パターンも書ける（§8.1）。

### 1.5 コメント

トークン先頭の `//` から行末までをコメントとする。コメントは項を作らない。

```
x = 1 ; // 次の行へ続く
1 <<< x
```

`x//y` は一つの名前、`x //y` は名前 `x` に続くコメントとなる。コメント中の括弧も無視する。

「式とそれに続く `;`」をまとめて取り除くと、取り除く項数は偶数になり、残りの項数の奇偶は保たれる。ただし、末尾の式だけを取り除いて `;` を残すと、式が定義に変わる場合がある（§10）。

## 2. 括弧と偶奇

括弧は `()` と `{}` の2種類であり、対応する種類で閉じる。対応しない括弧、閉じ忘れ、余分な閉じ括弧は構文エラーとなる。

### 2.1 偶奇規則

各括弧の中身の項数を、次の順で分類する。

| 項数 | 意味 |
|---|---|
| 0 | ユニット値 `()`。空の `{}` も同じ値 |
| 2 | 構文エラー |
| 奇数 | 式 |
| 4以上の偶数 | 関数定義 |

式は「オペランド（オペレータ オペランド）*」の形を取る。1項の式は、その項を評価する。

定義は先頭3項をシグネチャ、残りを本体の式とする。本体の項数が奇数なので、全体は偶数項になる。この分類は、偶数項を定義に割り当てるという規則を前提にしている。

```
(a plus b a + b)
```

シグネチャは `a plus b`、本体は `a + b` で、計6項である。左仮引数名は `a`、関数名は `plus`、右仮引数名は `b` となる。

```
(a plus b (a + b))
```

これも同じ動作の関数を定義する。こちらは本体の `(a + b)` を外側から1項と数えるので、計4項である。内側の項数を外側へ足し合わせない。

シグネチャの項は評価しない。現行処理系は、シグネチャに引用符なしの名前以外があってもエラーにしない。その位置に対応する名前を持たない定義として扱う。関数名がなければ束縛を作らず、仮引数名がなければ対応する引数の値を束縛しない。これにより、`;` の欠落で偶数項になったコードも定義として受理される（§10）。

2項の検査は、実行前に入れ子の括弧も含めて行う。実行されない分岐の中にあってもエラーとなる。

### 2.2 `()` と `{}`

| 括弧 | 式の場合 | 定義の場合 |
|---|---|---|
| `()` | 現在の環境で評価する | 現在のフレームに定義し、その関数値を返す |
| `{}` | 新しい子フレームで評価する | 新しい子フレームに定義し、その関数値を返す |

空の括弧はどちらもユニット値を返す。

```
x = 1 ; {x = 2 ; (1 <<< x)} ; (1 <<< x)
```

標準出力は `21`。内側で作った `x` の束縛は外側の `x` を変更しない。

`{a plus b a + b}` の名前 `plus` は外側へ公開されない。ただし返される関数は子フレームを保持するため、本体からはその名前を参照できる。「外側に名前を残さない関数」であって、内部にも名前がないという意味ではない。

### 2.3 再帰

関数は定義先の環境を保持するクロージャである。定義時に、その環境へ関数自身を束縛する。本体はその束縛を参照できるため、再帰呼び出しが可能となる。

```
(n fact d (n <= 1) ? 1 : {n * ((n - 1) fact d)}) ;
1 <<< (5 fact ())
```

標準出力は `120`。`d` はこの例では使用しない右仮引数である。`{}` で定義した関数も、保持している環境を通じて自身の名前を参照できる。

### 2.4 トップレベル

ファイル全体を暗黙の `()` として扱う。トップレベルにも同じ項数規則が適用される。

```
(a plus b a + b) ;
1 <<< (2 plus 3)
```

標準出力は `5`。定義を囲む括弧は外側で1項であり、トップレベルは「定義・`;`・出力式」の項を含む奇数項の式となる。

## 3. 適用

関数の適用は常に中置の二項適用である。

```
2 plus 3
```

左引数は `2`、関数は `plus` から取得した値、右引数は `3` である。オペレータ位置には名前だけでなく引用文字列や括弧も置ける。名前は束縛から、引用文字列はその内容から、括弧はその評価値から適用対象を得る。

ユーザー定義関数の呼び出しでは、定義時に保持した環境の子フレームを作り、左右の引数値を仮引数名に束縛して本体を評価する。左右の仮引数名が同じなら右の値が残る。本体の評価値を呼び出しの結果とする。

すべての関数は2引数である。使わない側にも引数を渡す。3個以上の値を渡す規約としては、関数を返して段階的に適用する方法と、cons にまとめる方法がある（§8.10）。0引数・1引数の専用呼び出し構文はない。

関数でない値を適用対象にした場合は、左右を評価し、適用対象と左右の値を持つ記号項を返す（§7、付録）。

## 4. 優先順位

oddity は、演算子の優先順位を実行時の束縛から取得する。これは字種から演算子を分類しないこととは別の設計上の規則である。

括弧内の項列は、評価直前まで平坦な列として保持する。式を評価するとき、オペレータ位置の項の順位に従って二項適用の木に組み立てる。この処理を**グルーピング**と呼ぶ。

### 4.1 デフォルトと初期値

初期環境の順位は次の通り。数値が大きいほど強く結合する。

| 順位 | 名前 |
|---|---|
| 1 | `;` |
| 2 | `=` |
| 3 | `<<<` `>>>` `!!` |
| 4 | `?` `:` `!` `\|\|` `&&` |
| 5 | `==` `!=` `<` `>` `<=` `>=` |
| 6 | `\|>` `$` |
| 7 | `,` |
| 8 | `+` `-` `*` `/` `%` `++` `<>` `#` `@` `~` `<<-` `->>` `<->`、およびデフォルト |

同順位は左結合とする。したがって `1 + 2 * 3` の評価値は `9` である。

オペレータ位置が引用符なしの名前なら、その束縛の順位を使用する。メタデータを持たない束縛や未束縛の名前はデフォルト順位8とする。引用文字列と括弧も、値を評価せずデフォルト順位8とする。

### 4.2 グルーピング規則と例

複数の適用を含む列では、最も弱いオペレータのうち最も右の位置を根に選び、その左右を再帰的にグルーピングする。同順位で右を根にすることにより、左結合になる。

```
x = 1 ; y = x + 2 ; 1 <<< y
```

これは `((x = 1) ; (y = (x + 2))) ; (1 <<< y)` と結合し、標準出力は `3` となる。

### 4.3 順位によって変わるもの

初期順位では、次のように括弧を省略できる。

- `a , b = 1 , 2` は `(a , b) = (1 , 2)` となる。
- `x = b ? t : f` は `x = ((b ? t) : f)` となる。
- `1 <<< a == b` は `1 <<< (a == b)` となる。

これらは順位の選択に依存する。順位が変わっても、字句の区切りや項数による式・定義の分類は変わらない。

ハイライトは、項の位置からオペランド・オペレータや定義の名前を区別できる。一方、実行時の環境を使わずに、すべての実行について演算子の結合や適用対象を確定することはできない。

### 4.4 束縛のメタデータ

プレリュードの演算子の束縛は、次の情報を持つ。

| フィールド | 内容 |
|---|---|
| 適用対象 | 2引数関数 |
| 優先順位 | グルーピングに用いる順位 |
| 左の評価方針 | 正格または遅延 |
| 右の評価方針 | 正格または遅延 |

名前をオペレータ位置で使うと、関数と評価方針を参照する。オペランド位置で参照すると、メタデータを除いた関数値を取得する。

メタデータを持たない値の束縛は、順位8・左右とも正格として扱う。現行版には、ユーザーがメタデータ付き束縛を構成する手段はない。`f = ?` は関数値だけを束縛するため、`f` の順位と評価方針は `?` と異なる（§5）。

### 4.5 グルーピングのタイミング

括弧の式は、その括弧を評価する直前に一括でグルーピングする。`;` ごとには分割し直さない。関数本体は呼び出すたびにグルーピングする。

優先順位はグルーピング時に、適用する関数と左右の評価方針は各適用の実行時に取得する。そのため、ブロック途中の再束縛は、そのブロックですでに決まった結合を変えないが、後続の適用対象や評価方針を変えうる。以降に評価する内側の括弧や、以降に呼ぶ関数本体では順位を取得し直す。

```
(1 <<< (1 + 2 * 3)) ; * = + ; (1 <<< (1 + 2 * 3))
```

標準出力は `96`。後半の `*` は加算の関数値に置き換わる。

## 5. 評価戦略

通常の適用は正格評価であり、左オペランド、右オペランドの順に評価して関数へ渡す。適用対象と評価方針は、その左右を評価する前に取得する。ユーザー定義関数は、渡された左右の引数を評価してから本体を実行する。

遅延と指定されたオペランドは、その時点では評価せず、構文木と呼び出し側環境の対として組み込み関数へ渡す。`=` は左の木を束縛先として検査する。`?`、`:`、`!` は条件に応じて右を評価する。`&&` と `||` も、それぞれ `?` と `:` と同じ評価方針を持つ。

これらを専用のパーサ構文ではなく、束縛の評価方針で扱う。ただし、ユーザー定義関数と組み込み関数の能力が同じという意味ではない。v0 の遅延機構は組み込みの束縛に限られる。

関数値を取り出して別名へ束縛すると、元の遅延フラグは失われる。`f = ?` の後の `b f t` は左右を評価してから呼び出す。`|>` と `$` も評価済みの引数を渡す（§8.10）。

## 6. 環境

### 6.1 フレーム連鎖

名前の参照は、内側から外側へ束縛を探す。

```
最内 → … → トップレベル → プレリュード → 数値解決 → 自己評価
```

トップレベルとプレリュードは別のフレームである。数値解決と自己評価は、現行処理系では表に格納した束縛ではなく、探索後の解決処理として実装する。

- **数値解決**：ASCII 数字列、または先頭の `-` と ASCII 数字列を、符号付き64ビット整数へ変換する。範囲外なら数として解決しない。`+1` はこの規則では数にならない。
- **自己評価**：それまでに解決できなかった名前を、綴りどおりの文字列値として返す。

このため未束縛名の参照自体はエラーにならない。数値解決は固定であり、ユーザーが差し替えることはできない。

### 6.2 束縛規則

`=` は呼び出し側の最内フレームだけに束縛を作る。同じフレームに同名の束縛があれば置き換える。親フレームの束縛は変更しない。

```
a = 1 ; a = 2 ; 1 <<< a
```

標準出力は `2`。`{a = 2}` は子フレームに束縛を作るため、親の `a` を遮蔽する。関数呼び出しでは、定義時の環境の子フレームが引数と本体の束縛先になる（§3）。

### 6.3 内側から外側への書き込み

`=` には親フレームへ書き込む操作がない。関数本体からトップレベルの束縛を参照することはできるが、同名の束縛を作っても呼び出し用フレームに作られる。

この制限は名前の束縛に関するものであり、入出力などの副作用を禁止するものではない。また、クロージャは環境を保持するので、その環境の既存束縛が外側の実行によって置き換わると、新しい値を参照する。

### 6.4 数の遮蔽と数値解決

数字の綴りも名前なので、通常の束縛で数値解決より先に解決できる。

```
1 = 1 + 1 ; 2 <<< 1
```

標準エラーへ `2` を出力する。右辺の `1` は初期状態の数として解決され、束縛後の `1` はその束縛値を参照する。もう一度 `1 = 1 + 1` を実行すれば、同じフレームの束縛を `4` に置き換える。

数値解決の機構自体は変更されない。内側に `{}` を追加しても外側の遮蔽は見えるため、それだけでは元の数へ戻らない。`"1"` は文字列を返し、数が必要なら `"1" ~ 10` で明示的にパースできる（§8.9）。

## 7. 値とリテラル

プログラムで扱う値は、整数・文字列・関数・cons・ユニット・記号項である。メタデータ付きの束縛は、通常の参照では関数値として取得する（§4.4）。

- 整数は符号付き64ビットである。ソースの数字は数値解決を受ける名前であり、整数リテラルとして字句分類しない。
- 文字列は不変である。引用文字列は文字列値を直接返す構文である。
- 関数には組み込み関数とユーザー定義クロージャがある。
- cons は二つの値の組である（§8.2）。
- ユニットは空の括弧が返す値である。
- 記号項は適用対象と左右の値を保持するデータである。自動的な再評価や式変形は行わない。

整数同士の `+`、`-`、`*`、`/`、`%` はそれぞれ加算・減算・乗算・整数除算・剰余を返す。除算はゼロ方向へ切り捨て、剰余は被除数と同符号または0となる。整数以外への適用、オーバーフロー、ゼロ除算では記号項を返す。

印字では、整数は十進表記、文字列は引用符なしの内容、ユニットは `()`、組み込み関数はその綴りを使用する。ユーザー定義関数は `<fn 名前>`、名前がなければ `<fn>` と表示する。cons は左ネストを平坦化した `(a , b , c)`、記号項は `(左 適用対象 右)` と表示する。印字結果から値の種類を一意に復元できるとは限らない。

### 7.1 真偽

偽として扱う値はユニット `()` だけである。整数0、空文字列、関数、cons、記号項はすべて真として扱う。独立した真理値型や真理値リテラルはない。

`()` は名前の参照ではないため、同じ綴りの名前を束縛して遮蔽することはできない。予期される失敗にもこの値を用いる（§8.7）。

## 8. プレリュード演算子

以下は初期環境の組み込み演算子を記述する。再束縛後には、元の名前の動作や評価方針が保たれるとは限らない。

| 名前 | 左 | 右 |
|---|---|---|
| `=` | 遅延 | 正格 |
| `?` `:` `!` `\|\|` `&&` | 正格 | 遅延 |
| その他 | 正格 | 正格 |

順位は §4.1 に示す。

### 8.1 `=` — 束縛

左を評価せず、束縛先のパターンとして検査する。許される形は、引用符なしの名前、またはその名前を `,` で組み合わせた二分木である。空でない奇数項の `()` は、内部をグルーピングして透過的に検査する。引用文字列、`{}`、空の `()`、定義、`,` 以外の適用はパターンにできない。

この検査は `=` の実行時に行う。字句・括弧・2項の検査とは異なり、実行されない `=` の左辺は検査しない。不正な左辺は処理系エラーとして実行を終了する（§9）。

```
a , b = 1 , 2        → a に1、b に2を束縛
x = a , b            → x に cons の値を束縛
x = y = 1            → 左結合で (x = y) が左辺になり、実行時エラー
```

右辺を評価し、パターンの各名前には対応する値を束縛する。名前の葉は任意の値と対応し、`,` の節は cons とだけ対応する。対応に必要な cons 構造がない場合はマッチ失敗となり、`()` を返す。成功時は右辺の値を返す。

束縛の書き込みは、パターン全体のマッチ成功後に行う。失敗したマッチによる部分的な束縛は残さない。ただし、右辺の評価で発生した副作用を取り消すものではない。同じ名前が複数ある場合は左から右の順に書き込み、後の値が残る。

```
rest , y , z = 1 , 2 , 3 , 4
```

`rest` は `(1 , 2)`、`y` は `3`、`z` は `4` となる。これは左ネストのリストに対する末尾寄せの部分マッチである。右ネストしたパターンは、対応する右ネストの cons を要求する。葉に定数や `()` を指定して値の一致を検査する機能はない。

評価済みの値として左引数を渡された場合は、束縛を行わず `()` を返す（§8.10）。

### 8.2 `,` — Cons

`a , b` は二つの値を持つ cons を返す。`,` は左結合なので、`a , b , c` は `(a , b) , c` となる。

本書で「リスト」と呼ぶのは、cons の左側をたどって得る要素列（左スパイン）である。cons でない値は1要素のリストとして扱う。空リストを表す専用の値や暗黙の終端はない。

- `((1 , 2) , 3)` と `(1 , 2 , 3)` は同じ構造である。
- `(1 , (2 , 3))` は、右側に cons を持つ別の構造である。
- `()` を終端として使う規約をプログラム側で設けることはできる。ただし組み込みの添字・連結は、その規約を特別扱いしない。

分割代入のマッチ結果で、値が必要な cons 構造を持つか判定できる（§8.1）。

### 8.3 `?` `:` `!` — 分岐

三つはそれぞれ独立した二項演算子であり、左は正格、右は遅延である。

| 式 | 左が真の場合 | 左が偽の場合 |
|---|---|---|
| `b ? t` | `t` を評価して返す | `t` を評価せず `()` |
| `x : y` | `y` を評価せず `x` | `y` を評価して返す |
| `x ! y` | `y` を評価せず `()` | `y` を評価して返す |

`&&` は `?`、`||` は `:` と同じ動作をする。

`b ? t : f` は `(b ? t) : f` と結合する。`b` が偽なら `f` を評価する。`b` が真でも、`t` の評価値が `()` なら `f` を評価する。この点で、条件だけによって一方の枝を選ぶ三項条件演算子とは異なる。

```
1 <<< (1 ? () : "f")
```

標準出力は `f`。`?` は非局所的な早期リターンを行わず、その適用の値を返すだけである。

`b ! 1` は、`b` が真なら `()`、偽なら `1` を返し、否定として使える。`b ? () : 1` は真偽どちらでも `1` を返すため、否定にはならない。

`?` と `:` でも、枝の値を非ユニットの cons に包み、最後に取り出すことで同様の処理を記述できる。`!` はその包装を必要としない組み込み演算子である。

### 8.4 `<<<` `>>>` `<<-` `->>` `<->` — 入出力

fd は処理系の入出力先を指定する整数である。初期状態では0が標準入力、1が標準出力、2が標準エラーを指す。

| 式 | 動作・戻り値 |
|---|---|
| `fd <<< x` | `x` の印字形を書き込み、`fd` を返す。改行は付加しない |
| `fd >>> n` | 最大 `n` 文字を読み、文字列を返す |
| `fd >>> ()` | 1行を読み、末尾の LF とその直前の CR を除いた文字列を返す |
| `fd <<- path` | 読み込み専用で開き、fdを返す |
| `fd ->> path` | 書き込み専用で開く。作成し、既存ファイルは切り詰める |
| `fd <-> path` | 読み書きで開く。なければ作成し、既存内容は切り詰めない |

ファイルを開く演算子の左が `()` なら、3以上で未使用の最小fdを割り当てる。整数ならそのfdを使用し、既存の入出力先があれば置き換える。パスには右の値の印字形を用いる。開けない場合は `()` を返す。明示的な close 演算子はなく、通常は処理系の実行終了時に解放する。fdの置き換え時には以前の入出力資源も解放される。

`<<<` は左が整数でなければ記号項を返す。書き込み先がない場合や書き込み失敗は報告せず、左の整数を返す。`>>>` は左が整数、右が整数またはユニットでなければ記号項を返す。読み込み先がない場合や読み取りの失敗は `()` を返す。

文字数は Unicode スカラー値で数える。現行 Rust 処理系では、文字数指定読みで不正な UTF-8 を置換文字として扱い、行読みで不正な UTF-8 を含む場合は失敗とする。`n <= 0` の文字数指定読みは、読み取り可能なfdなら空文字列を返す。正の文字数でEOFまでに一部を読めた場合は、その部分を返し、一文字も読めなければ `()` を返す。空行は空文字列を返すため、EOFとは区別できる。

```
1 <<< "Hello, " <<< "world!" <<< "\n"
```

`<<<` はfdを返すため、各適用が同じ出力先へ連鎖する。式の値を印字してその値も返したい場合は、一時束縛を使用する。

```
t = 2 + 3 ; 1 <<< t ; t
```

読み取りは、読み込みに入る前にすべての書き込み先をフラッシュする。通常終了では標準出力をフラッシュする。`!!` では標準エラーをフラッシュするが、標準出力のフラッシュは保証しない。そのため、まだバッファにある出力が失われる場合がある。

ブラウザ版は標準入出力をメモリ上で扱い、ファイルを開く操作は失敗して `()` を返す。ホストのファイルシステムは公開しない。

### 8.5 `;` — 逐次

左を評価し、次に右を評価して、右の値を返す。左の値は戻り値として使用しない。初期順位は最弱である。末尾へ付ける文区切りではなく、左右の項を必要とする演算子である。

```
1 <<< "a" ; 1 <<< "b"
```

標準出力は `ab`。どちらかの評価が実行を中断した場合、その後は実行しない。

### 8.6 `!!` — 中断（panic）

左右を評価した後、右の印字形と改行を処理系のfd 2へ書き込み、実行を中断する。左が整数なら下位8ビットを終了コードとし、それ以外なら1とする。catch はない。

```
1 !! "disk full"
```

標準エラーに `disk full` と改行を出し、終了コード1で終了する。`256 !! "message"` は終了コード0になる。

fd 2は処理系が直接指定する。ソース中の名前 `2` の再束縛は `2 <<< x` の出力先を変えるが、`!!` が指定するfd番号は変えない。ただし、ファイルを開く操作によるfd 2自体の置き換えは影響する。

### 8.7 失敗と実行の中断

| 種類 | 表現 | 処理 |
|---|---|---|
| 予期される失敗 | `()` | `?`、`:`、`!` で値として処理できる |
| 明示的な中断 | `!!` | 終了コードを指定して実行を終了する |
| 処理系が検出する不正 | 診断 | 字句・構文・左辺形の不正などで終了する |

マッチ失敗、ファイルを開けない場合、数値パース失敗などは `()` を返す。プログラム側でこれを中断へ変換できる。

```
(a , b = 5) : {1 !! "not a pair"}
```

`!!` や処理系エラーを捕捉し、値へ変換して続行する機構はない。記号項を返す演算は、これらの中断とは区別する。

### 8.8 `==` `!=` `<` `>` `<=` `>=` — 比較

比較が成立したときは右オペランドを、成立しないときは `()` を返す。ただし、左右のどちらかが `()` なら、比較の種類によらず `()` を返す。

`==` は整数・文字列を内容で、consと記号項を再帰的な構造で比較する。ユーザー定義関数は同じ関数実体への参照なら等しく、組み込み関数は同じ組み込みなら等しい。異なる種類の値は等しくない。`!=` はユニット伝播の規則を除いてこの判定を反転する。

順序比較は整数同士または文字列同士に定義する。文字列は Unicode スカラー値順の辞書式比較とする。それ以外の組み合わせは記号項を返す。記号項は真として扱われるため、比較可能でない値にも一般的な真偽判定が得られるとは限らない。

```
1 < 2 < 3
```

`(1 < 2) < 3` と結合し、最初の比較が `2`、次の比較が `3` を返す。途中が不成立なら、以降もユニット伝播によって `()` となる。左右とも正格なので、後続のオペランド評価を短絡する比較構文ではない。

### 8.9 文字列演算

`a ++ b` は文字列同士を連結する。それ以外の組み合わせは記号項を返す。文字列の添字は `@` を使用する（§8.11）。

文字列は数へ暗黙に変換しない。数値フレームが解決するのはソース中の名前であり、実行時の文字列値ではない。

```
("1" ++ "2") + 1    → 評価値は記号項 (12 + 1)
```

`str ~ radix` は文字列を符号付き64ビット整数としてパースする。基数は整数2〜36とし、先頭の `+` または `-` を認める。前後の空白を除去せず、数字に使う英字は大文字小文字を区別しない。不正な数字列、範囲外、基数や引数の種類が不正な場合は `()` を返す。

```
("42" ~ 10)    → 評価値 42
("2a" ~ 16)    → 評価値 42
("42" ~ ())    → 評価値 ()
```

文字列 `"1"` と整数 `1` は等しくない。印字結果はどちらも `1` になる。空文字列同士の `==` は右の空文字列を返し、その値は真である。

### 8.10 `|>` `$` — 値による適用

`(l , r) |> f` と `f $ (l , r)` は、consから左右の値を取り出し、関数値 `f` に適用する。consでない値を引数組に指定すると記号項を返す。

```
(a plus b a + b) ;
1 <<< (2 , 3 |> plus)
```

標準出力は `5`。直接の中置適用でも括弧の評価値を関数にできるが、これらの演算子は、すでに値となった引数組を分解して渡す用途を持つ。

`1 , 2 , 3 |> f` は、左引数 `(1 , 2)` と右引数 `3` を渡す。段階的な関数適用 `((x f y) g z)` とは異なる引数規約であり、関数の利用者はどちらを要求するか把握する必要がある。

`|>` と `$` は正格で、関数にも評価済みの引数を渡す。元の束縛の遅延フラグは持ち運ばない。そのため `?`、`:`、`!` を渡しても短絡せず、`=` を渡しても束縛できず `()` となる。

### 8.11 `#` `@` `<>` — 添字と連結

| 式 | 動作 |
|---|---|
| `list # n` | 左スパインを先頭から0始まりで数え、要素を返す |
| `str @ n` | Unicode スカラー値を先頭から0始まりで数え、1文字の文字列を返す |
| `a <> b` | `b` の左スパインの要素を順に `a` へconsする |

`#` は整数の負数・範囲外の添字に `()` を返し、整数でない添字には記号項を返す。consでない値に対する `# 0` はその値を返す。`@` は非負整数の範囲外には `()` を返し、負数または引数の種類が不正なら記号項を返す。

`#` の処理時間は現行実装では左スパインの長さに比例する。`@` は指定位置まで文字をたどる。文字数はバイト数や表示上の文字のまとまりとは異なる。

`<>` は右辺の左スパインの長さに比例する。空リストを組み込みで持たないため、連結の単位元はない。`()` も通常の1要素として扱う。

### 8.12 `()` と等値比較

`(() == ())` と `(() != ())` は、どちらもユニット伝播の規則により `()` を返す。これは §8.8 で定める比較演算子の動作であり、ユニット値を検査したい場合は §8.3 の分岐演算子を使う。

ユニットを含むconsなどの構造比較では、その内部のユニット同士は等しいものとして比較する。比較演算子が直接ユニットを受け取る場合の伝播規則とは区別する。

## 9. プログラムの評価と終了

式も定義も評価値を持つ。`=` は成功時に右の値、`<<<` はfd、関数定義は関数値を返す。プログラム全体も一つの括弧として評価し、その最終値は実行結果の出力や終了コードには使用しない。

- 通常終了のコードは0である。
- `!!` が実行された場合は、その指定によるコードで終了する（§8.6）。
- 字句・構文の不正、不正な束縛左辺などの処理系エラーは、診断を伴いコード1で終了する。
- CLIの引数不正やソースファイルの読み込み失敗はコード2となる。

裸の式の値を表示するには `1 <<< 式` と書く。`!!` はプログラムが終了コードを明示する演算子であるが、処理系やCLI自体の失敗が別途存在する。

現行 Rust 処理系には再帰深さ50,000の制限がある。ブラウザ版は深さ500と実行量の制限を持つ。これらの制限に達した場合も通常の評価値は返さず、実行を終了する。ホストの資源不足による失敗は別途起こりうる。

## 10. 地雷一覧（書き方と結果の注意点）

ここでは、既存言語の書き方から誤読しやすい例をまとめる。各動作の規則は参照先で定める。

**空白とコメント（§1）**

- `x+y` は一つの名前である。`x + y` とは異なる。
- `a == b` の `==` を分けて `a = = b` とすると、4項の定義になる。2番目の `=` は関数名として扱われる。
- `a // b` の `//` は整数除算ではなくコメントである。同じ行の閉じ括弧もコメントに入る。`x//y` は一つの名前になる。

**項数の変化（§2）**

```
(1 <<< "a") ; (1 <<< "b") (1 <<< "c")
```

全体が4項の定義になり、標準出力は空、終了コードは0となる。先頭3項はシグネチャなので、内部の出力式も評価しない。2項になった場合は構文エラーとなる。

`a ; b ; c` の末尾の `c` だけを削除すると、`a ; b ;` は4項の定義となり、`;` という名前の関数を定義する。`;` は末尾に置く文区切りではない。

**名前とfdの再束縛（§4、§6、§8.4）**

- `1 = 1 + 1` を同じフレームで繰り返すと、名前 `1` の値は2、4、8と変わる。
- `2 = 5` の後の `2 <<< x` はfd 5へ書こうとする。fd 5がなければ出力は捨てられる。`!!` の直接指定するfd 2は、この名前の遮蔽の影響を受けない。
- `1 = 0` の後の `1 !! err` はコード0で中断する。
- `, = 0` は順位0を設定する操作ではない。`,` を整数値で置き換え、その順位はデフォルト8となる。後続のグルーピングや適用に影響するが、左辺パターン検査は依然として綴り `,` を認識する。
- `!! = <<<` の後の `1 !! err` は中断せず、標準出力へ書き込む。クロージャも、保持した環境の束縛変更を参照する。ただし別のフレームで遮蔽した場合は、その範囲だけに影響する。

**値と分岐（§7、§8.3、§8.8）**

- `1 <<< hello` は名前 `hello` の束縛に依存する。文字列を確実に出したい場合は `1 <<< "hello"` と書く。
- `b ? () : f` は、`b` が真でも `f` を評価する。
- 順序比較が記号項を返す場合、その値は真として扱われる。

**ファイルとバッファ（§8.4）**

- `->>` は追記ではなく、切り詰め書き込みである。
- 改行を含まない出力の後で `!!` を実行すると、標準出力の未フラッシュ部分が失われる場合がある。入出力先・実行環境にも依存するため、常に全出力が失われるという規則ではない。

## 11. v0 の範囲と処理系依存事項

本書は v0 の現行動作を対象とする。過去の「未決定事項」に含まれていた、文字数指定の読み取り、`~` による数値パース、引用の固定、close演算子を設けない方針、最終評価値を終了コードに使わない方針は、各節の規則に反映している。

整数幅、算術失敗時の記号項、印字形式、シグネチャに名前以外が来た場合の扱い、入出力の失敗時の扱いについても、現行 Rust 処理系に合わせて明記した。ブラウザ版のファイルアクセスと資源制限は §8.4、§9 に記述する。

ファイルのパス解釈、権限、実際のバッファリング、ホストの資源制約は実行環境に依存する。現行処理系の仕様を変更する場合は、実装・テスト・本書の対応を確認する。

## 12. v1 以降の構想

以下は v0 の機能ではなく、将来の検討事項である。

- 環境を値として公開する。
- メタデータ付き束縛をユーザーが構成できるようにする。
- 構文木と環境を保持する遅延引数を第一級にし、繰り返し評価できるようにする。
- 環境の値を利用したレコード・モジュールを検討する。

これらには追加の規則が必要であり、環境を値にするだけで動作が確定するものではない。v0 の反復は再帰で記述する。

`<<` と `>>` は将来のビットシフト用の候補として空けてある。現行プレリュードには束縛がなく、通常の未束縛名として自己評価する。数値解決器の差し替えは v0 では提供しない。

## 付録: 記号項と表記の例

束縛のない `x` と `y` は文字列となり、数値加算できないため記号項を返す。

```
1 <<< (x + y)
```

標準出力は `(x + y)`。関数でない値の適用も記号項になる。ただし、次の例の `+`、`*`、`/` は未束縛ではなく、初期環境の組み込み関数である。

```
1 <<< (+ * /)
```

中央の `*` に、関数値 `+` と `/` を渡す。整数同士ではないので記号項となり、標準出力は `(+ * /)` となる。

名前へ値を束縛すれば、別の綴りでも数を参照できる。

```
一 = 1 ; 二 = 2 ; 1 <<< (一 + 二)
```

標準出力は `3`。これは個別の名前への束縛であり、数値解決器そのものを変更しているわけではない。
