oddity

奇数項なら式、偶数項なら宣言。

項数の奇偶が意味を決める言語。すべての関数は2引数で、トークンに字種の区別はない。役割は括弧の中の位置だけで決まり、優先順位は実行時に環境から引かれる。

(n fact d
    (n <= 1) ? 1 : {n * ((n - 1) fact d)}
) ;
1 <<< "10! = " <<< (10 fact ()) <<< "\n"
10! = 3628800

3項のシグネチャ + 5項の本体 = 8項。偶数なので関数宣言になる。ループは再帰しかなく、let rec も Y コンビネータも要らない。

Concept

規則は最初の2つだけ。あとの2つはそこから導出される。

空白が唯一の区切り

(x + y) は3項で演算。(x+y) は1項で、x+y という名前の変数への参照。1-1 は数ですらない。

すべての関数は2引数

適用は常に中置で、関数呼び出し構文は存在しない。演算子適用そのものが呼び出しになる。+ も fact も同格。

項数の奇偶が意味を決める

奇数項なら式で、奇数番目がオペランド、偶数番目がオペレータ。4以上の偶数項なら関数宣言で、シグネチャ3項＋本体。0項はユニット値、2項は構文エラー。

順位は束縛の属性

トークンが ; か + かをパーサは知りようがない。だから静的な優先順位表を持てない。順位は括弧を評価する直前に、環境から引く。

空白1つで別の言語になる

x = 2 ; y = 3 ; 1 <<< (x + y)
5
x = 2 ; y = 3 ; 1 <<< (x+y)
x+y

後者は未束縛トークンなので、自己評価フレームが綴りどおりの文字列を返す。未定義エラーは存在しない。

Highlighting

構文ハイライトは原理的に不可能。ただし1種類だけ例外がある。

順位が実行時の値である以上、どう結合するかは静的には塗れない。役割のほうは括弧の対応が取れた時点で確定する。このページのコードはすべて、処理系本体のレキサとパーサが返した役割そのままで塗ってある。

オペランド オペレータ 仮引数 関数名 構文エラー

そのため書き間違いが目で見える。== の途中に空白を1つ入れると4項＝偶数＝関数宣言になり、シグネチャの2番目が関数名として潰される。構文エラーは出ない。

1 <<< (a == b)
()
1 <<< (a = = b)
<fn =>

== != !! <= >= <<< >>> ++ |> && || ->> のすべてが同じ形の地雷を持つ。

Tour

位置で決まる世界の歩き方。

すべての関数は2引数、適用は常に中置 §3

関数呼び出し構文は存在しない。演算子適用そのものが呼び出しで、+ も fact も同格。1引数が欲しければダミー引数、3引数以上が欲しければクロージャを返す。

(a plus b (a + b)) ; 1 <<< (2 plus 3)
5

() と {} の差は、環境を汚すかどうかだけ §2.2

{} はフレームを1枚積む。同じ = が、囲む括弧の字種だけで「関数型の束縛」と「命令型の代入」を行き来する。

x = 1 ; {x = 2 ; (1 <<< x)} ; (1 <<< x)
21

再帰に let rec も Y コンビネータも要らない §2.3

{} の偶数項は無名関数を返す。捨てられるフレームの中に関数自身の名前が束縛されていて、クロージャがそのフレームを捕まえているから、名前は生き残る。

f = {n fact d (n <= 1) ? 1 : {n * ((n - 1) fact d)}} ; 1 <<< (5 f ())
120

? と : は独立した二項演算子 §8.3

(b ? t : f) は5項で、左結合により ((b ? t) : f)。偽が () だけなので、述語は「左が () か」の一つで足りる。? はガード、: は Elvis、3つ目の ! は unless。

1 <<< (1 ? "t" : "f") <<< (() ? "t" : "f") <<< (() ! "u")
tfu

リストに終端は無い。マッチが判定を兼ねる §8.2

, は二分木を作るだけで、リストとはその左スパインのこと。だから空リストが存在せず、isEmpty も要らない。要るのは isPair で、それは分割代入そのもの。

xs = 1 , 2 , 3 ; (rest , y = xs) ; 1 <<< rest <<< " と " <<< y
(1 , 2) と 3

マッチ失敗は () を返す §8.1, §8.7

予期される失敗は () で表して ? : で処理する。プログラマの誤りは !! で、こちらは catch が無いので必ず最外まで飛ぶ。昇格は1行で書ける。

1 <<< (a , b = 5)
()

演算子が何をするかは途中で変えられる §4.5

順位はグルーピング時に、関数は評価時に引かれる。同じ束縛の2つの側面が別のタイミングで参照されるので、中身の差し替えは即座に効くが、結合の仕方はそのブロックでは変わらない。

(1 <<< (1 + 2 * 3)) ; * = + ; (1 <<< (1 + 2 * 3))
96

Mines

仕様に「地雷一覧」という節がある。

どれも設計の帰結である。エラーが出ないものだけを選んである。

; を1つ書き忘れると、ブロックが静かに関数宣言に化ける

(1 <<< "a") ; (1 <<< "b") (1 <<< "c")
（何も出ない。終了コード 0）

4項＝偶数なので宣言になり、(1 <<< "a") と (1 <<< "b") はシグネチャとして評価されずに消える。ただし2文だけのブロックは守られる。; を落とすと2項＝構文エラーになるため。3文以上だけが黙って化ける。

1 = 1 + 1 は恒等式の顔をしたアキュムレータ

1 = 1 + 1 ; 2 <<< 1
2（標準エラーへ）

数値フレームは無限なので、= がそこで既存の束縛に当たることは原理的にない。遮蔽は常に「新規作成」＝積み増しになる。実行するたび倍。2 = 5 と書けば標準エラーが消える。

(b ? () : f) は真でも f を返す

1 <<< (1 ? () : "f")
f

真の枝の値が () だと : が必ず発火する。否定を素朴に (b ? () : 1) と書くと常に 1 になる。3つ目の短絡演算子 ! を組み込みで持つのはこのためである。

文字列と数は印字が同一で区別できない

1 <<< "1" <<< " " <<< 1 <<< " " <<< ("1" == 1)
1 1 ()

引用は型を導入しない。"1" は文字列 1 であって数ではないので、数値フレームを通らない。代わりに、数を潰したあとの un-shadow 手段になる。

数式処理系

未束縛トークンは綴りどおりの文字列に評価され、文字列を適用しようとして失敗すると記号項というデータが残る。専用機構はゼロ。

1 <<< (x + y) <<< " " <<< (+ * /)
(x + y) (+ * /)

難読化

役割が位置だけで決まるので、綴りは役割を示さない。下は FizzBuzz で、関数名が fopen（切り詰め書き込み）を潰している。1 ->> 5 は「fd 5 を開く式」に完全に化けている。

(<< ->> >> << > >> ! (1 <<< << % 15 == 0 ? "FizzBuzz" : (<< % 3 == 0 ? "Fizz") : (<< % 5 == 0 ? "Buzz") : << <<< "\n" ; << + 1 ->> >>)) ; 1 ->> 5
1 2 Fizz 4 Buzz

ハイライトで分かるのは、どれがオペレータでどれがオペランドかだけである。どう結合するかは実行時に決まるので、静的には分からない。

Get it

Rust で書かれた実装が1つある。

git clone https://github.com/todays-mitsui/oddity
cd oddity
cargo build --release

./target/release/oddity examples/fizzbuzz.odd
./target/release/oddity -e '1 <<< "Hello\n"'
./target/release/oddity --ast examples/fact.odd

依存クレートはゼロ。--ast は項の入れ子だけを表示する。結合は実行時に決まるので出せない。
