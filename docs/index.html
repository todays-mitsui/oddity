oddity

oddity は、二項演算子を定義して、適用するプログラミング言語です。

基本となる構成要素は、演算子の定義と適用。名前を空白で区切って並べ、演算子の左右に引数を置いて使います。

定義して使う

自分で作った演算子も、足し算と同じ形で。

まず、二つの数を足す式を見てみます。

2 + 3

左の引数が 2、演算子が +、右の引数が 3。評価値は 5 です。

同じ足し算をする演算子に、plus という名前を付けられます。

(a plus b a + b)

先頭の3項が定義のシグネチャです。a が左の仮引数、plus が演算子の名前、b が右の仮引数。残りの a + b が本体です。

2 plus 3

これで 2 + 3 と同じ形で呼び出せます。oddity の関数はすべて2引数で、関数呼び出しと二項演算子の適用は同じ書き方です。

ここまでのコードは説明用の断片です。まとめて実行し、結果を標準出力へ表示するなら、次のように書きます。

(a plus b a + b) ;
1 <<< (2 plus 3)
5

; は左から右へ実行を進める演算子です。1 <<< 値 は標準出力へ値を書き込みます。裸の式は評価されますが、その評価値は自動では表示されません。以降、コード直下の「→」は標準出力を示します。

名前の綴りより、並べた位置

x + y
x plus y

式では、奇数番目がオペランド、偶数番目がオペレータです。+ と plus に、記号か英字かによる文法上の区別はありません。定義の先頭3項には、先ほどの仮引数・名前・仮引数の役割があります。

x + y
x+y

名前同士は空白で区切ります。上は3項の式、下は x+y という一つの名前です。基本の書き方は名前を並べるだけですが、括弧によるまとまり、文字列の引用、コメントには字句上の規則があります。

定義と適用を、項数で区別する

式は「オペランド・演算子・オペランド……」と交互に並ぶため、項数が奇数になります。oddity は偶数項を定義に割り当てています。定義は「先頭3項のシグネチャ＋奇数項の本体」なので、全体は偶数項です。

先ほどの (a plus b a + b) は、シグネチャ3項と本体3項で、計6項です。本体を括弧でまとめても、同じ定義になります。

(a plus b (a + b))

こちらの中身は a、plus、b、(a + b) の4項。括弧でまとめた部分は外側からは1項と数え、内側の3項を足して6項とは数えません。

演算子の定義（関数宣言）

項数は括弧ごとに数えます。プログラム全体も暗黙の () で囲まれています。詳しくは言語仕様 §1〜3へ。

代入・逐次実行・条件分岐も演算子で

x = 2 ;
1 <<< (x + 3)
5

= は左の名前に右の値を束縛する演算子です。; も二項演算子で、左右を順に評価して右の値を返します。文法上の文区切りではないため、末尾に付ける書き方には注意が必要です。

1 <<< ((2 < 3) ? "yes" : "no")
yes

? と : はそれぞれ独立した二項演算子です。条件 ? 真側 : 偽側 は (条件 ? 真側) : 偽側 と結合します。偽を表す値は ()。? は左が真なら右を評価し、偽なら () を返します。: は左が () のとき右を評価します。

適用の形は共通でも、評価方法は演算子によって異なります。通常の関数は引数を評価してから呼ばれますが、= は左辺を名前やパターンとして扱い、? と : は右辺を必要なときだけ評価します。現行版では、こうした遅延フラグを持つ制御構造をユーザーが追加することはできません（言語仕様 §4.4・§5・§8）。

発展的な使い方

同じ形で、スコープや再帰へ。

括弧でスコープを作る

() は現在のスコープで評価し、{} は新しいスコープで評価します。次の例では内側の x が外側を遮蔽するため、順に 2、1 が表示されます。

x = 1 ; {x = 2 ; (1 <<< x)} ; (1 <<< x)
21

定義した名前で再帰する

関数の本体から自分の名前を参照できます。次の階乗は右の引数 d を使わないので、呼び出し時には () を渡しています。

(n fact d
    (n <= 1) ? 1 : {n * ((n - 1) fact d)}
) ;
1 <<< (5 fact ())
120

優先順位と再束縛

oddity は演算子の優先順位を実行時の束縛から取得します。初期状態では + と * は同順位・左結合なので、1 + 2 * 3 は (1 + 2) * 3 と結合します。

(1 <<< (1 + 2 * 3)) ; * = + ; (1 <<< (1 + 2 * 3))
96

最初は 9。* に + を束縛すると、次は (1 + 2) + 3 で 6 です。優先順位は各括弧の評価直前に、演算子の関数値は適用時に参照されます。詳しくは言語仕様 §4〜6へ。

位置によるハイライト

役割は位置から、結合は実行時の環境から。

このページは処理系のレキサとパーサが返す役割でコードを塗り分けています。括弧の対応と項数から、オペランド・オペレータや定義の名前を判別できます。演算子がどう結合するかは実行時の環境に依存します。

オペランドオペレータ仮引数関数名構文エラー

== の途中に空白を入れると、3項の式が4項の定義に変わります。ハイライトでは、2番目の = が定義の名前として表示されます。

1 <<< (a == b)
()
1 <<< (a = = b)
<fn =>

書き方と結果の注意点

項数や値の違いが、結果を変える。

; の書き忘れで定義になる

(1 <<< "a") ; (1 <<< "b") (1 <<< "c")
（標準出力なし。終了コード 0）

全体が4項になり、式として実行されず関数定義になります。先頭3項はシグネチャとして扱われます。2項になった場合は構文エラーですが、4以上の偶数項ではこのように定義として受理されます。

真側が () を返すと偽側も評価する

1 <<< (1 ? () : "f")
f

? が真側を評価しても、その結果が () なら : が右を評価します。一般的な三項条件演算子との違いです。偽のときだけ右を評価する演算子 ! もあります。

同じ表示でも、文字列と数は別の値

1 <<< "1" <<< " " <<< 1 <<< " " <<< ("1" == 1)
1 1 ()

"1" は文字列で、1 は数です。引用した文字列は名前の束縛を参照せず、そのままの値になります。比較は偽を表す () を返します。

再束縛による数字の遮蔽など、ほかの挙動は言語仕様 §10「地雷一覧」で紹介しています。

記号をデータとして扱う

計算できない式が、その形を残す。

束縛のない名前は綴りどおりの文字列に評価されます。数でない値への算術演算や、関数でない値の適用は、記号項というデータを返します。

1 <<< (x + y) <<< " " <<< (+ * /)
(x + y) (+ * /)

ここでは x と y に数を束縛していないため、足し算の形が残ります。(+ * /) では * を演算子、+ と / を引数として適用した形が表示されます。

ローカルで実行する

Rust の処理系で、ファイルを実行する。

git clone https://github.com/todays-mitsui/oddity
cd oddity
cargo build --release

./target/release/oddity examples/fizzbuzz.odd
./target/release/oddity -e '1 <<< "Hello\n"'
./target/release/oddity --ast examples/fact.odd

--ast は項の入れ子を表示します。演算子の結合は実行時に解決されるため、この表示には含まれません。
